**Shadow is an open-source (Apache-2.0) privacy layer for AI traffic.** It replaces names, emails, customers, secrets and IDs in prompts with realistic, reversible fakes before a request reaches OpenAI, Anthropic, Gemini or another provider, and restores the real values in the response, including streamed responses and tool calls. This page maps the other tools people use to stop sensitive data leaking into large language models, and links to a detailed, fair comparison with each one.

:::note[How we compare]
Every comparison is based on public documentation, checked on the review date shown on each page. Where a vendor's documentation does not say something, we say "not documented" rather than guess. Detection accuracy is compared on the [benchmarks page](/shadow/benchmarks/), with code and label mappings published, not on this page.
:::

## What kinds of tools prevent AI data leaks?

Tools in this space fall into five groups. They overlap, and many teams combine two.

| Category | What it does | Typical action on sensitive data | Examples |
|---|---|---|---|
| **Detector libraries and models** | Find PII spans in text. You build the rest | Placeholder, mask or hash, usually one way | Presidio, GLiNER-PII, OpenAI Privacy Filter, DataFog, cloud PII APIs |
| **Guardrail frameworks and AI gateways** | Sit in front of model APIs, route traffic and run checks | Block, or redact with placeholders; a few restore | LLM Guard, NeMo Guardrails, LiteLLM, Portkey, Kong, Cloudflare, Bedrock Guardrails |
| **Enterprise GenAI DLP** | Watch employees' use of AI apps in the browser, on the endpoint or in the SASE layer | Block, warn, coach, sometimes redact | Netskope, Zscaler, Palo Alto, Microsoft Purview, Nightfall, Harmonic, Prompt Security, Lasso, Strac |
| **Privacy vaults and secure-AI platforms** | Tokenise or pseudonymise data and re-identify under policy | Reversible tokens, usually as SaaS | Skyflow, Protecto, Private AI, Tonic Textual, Wald.ai |
| **Local reversible proxies** | Mask on the endpoint, restore in the response | Reversible placeholders or fakes | **Shadow**, Rehydra, a few small projects |

Shadow belongs to the last group. Its distinguishing choices are realistic, format-preserving fakes drawn from a persistent [persona](/shadow/concepts/personas/), restoration in [streams and tool calls](/shadow/concepts/tool-calls/), an [intent-aware policy](/shadow/concepts/intent-policy/), [file masking](/shadow/concepts/file-masking/) for Office documents, and a local, single-binary deployment as an [HTTPS proxy](/shadow/integrate/proxy-mode/), a [gateway](/shadow/integrate/gateway-mode/) or a [Rust library](/shadow/integrate/rust/).

## How do I choose an AI data-leak prevention tool?

Start from three questions: **who sends the data**, **what must happen to it**, and **who has to run the tool**.

1. **Employees pasting into ChatGPT, Gemini or Copilot in the browser, across a whole company?** You need visibility, policy and coaching across many managed devices. Choose an enterprise GenAI DLP or SASE product ([Netskope](/shadow/compare/netskope/), [Zscaler](/shadow/compare/zscaler/), [Microsoft Purview](/shadow/compare/microsoft-purview/), [Nightfall](/shadow/compare/nightfall/), [Harmonic](/shadow/compare/harmonic-security/)). These mostly block or warn.
2. **Developers, agents and apps calling model APIs, where answers must stay useful?** Blocking breaks the tool and plain redaction loses meaning. Choose a reversible layer that restores values in responses and tool calls: Shadow (local, open source), or a vault service such as [Skyflow](/shadow/compare/skyflow/) or [Protecto](/shadow/compare/protecto/) if you prefer a managed service.
3. **Building your own pipeline and only need detection?** Use a detector: [Presidio](/shadow/compare/presidio/), [GLiNER](/shadow/compare/gliner-pii/), [OpenAI Privacy Filter](/shadow/compare/openai-privacy-filter/) or a cloud PII API. Shadow can use Presidio and both open-weight models as additional detectors.
4. **Already standardised on an AI gateway?** Check its PII features first: [LiteLLM](/shadow/compare/litellm/), [Kong](/shadow/compare/kong-ai-gateway/), [Portkey](/shadow/compare/portkey/), [Cloudflare](/shadow/compare/cloudflare-ai-gateway/). Shadow can sit in front of a gateway as a sidecar, so masking happens before traffic leaves the host.
5. **Need de-identified datasets for training or analytics, not live traffic?** Use a batch tool such as [Tonic Textual](/shadow/compare/tonic-textual/) or [Google Sensitive Data Protection](/shadow/compare/google-sensitive-data-protection/).
6. **Must the data never leave your network, and must the tool be auditable?** Prefer open-source, self-hosted tools: Shadow, Presidio, LLM Guard, LiteLLM, NeMo Guardrails, Rehydra.

:::tip[A common combination]
Enterprise DLP for browser chat on managed devices, plus Shadow on developer machines, CI runners and services that call model APIs. The DLP product sees what employees type into web apps; Shadow keeps API, agent and file traffic useful while masked.
:::

## What Shadow does not do

Being honest about the gaps helps you choose:

- **No central fleet console.** There is no admin dashboard, SIEM export or user coaching. Configuration is a file per machine or container.
- **No OCR.** Text inside images and scanned PDFs is not detected. See [file masking](/shadow/concepts/file-masking/#limitations).
- **Detection is best effort.** Regex, checksums, dictionaries and optional NER models miss things. Multilingual recall is being measured; see the [benchmark](/shadow/benchmarks/).
- **It protects content, not identity.** Providers still see your IP address and the account behind your API key. See the [security model](/shadow/reference/security/).
