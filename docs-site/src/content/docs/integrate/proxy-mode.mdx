In proxy mode, tools send their traffic to Shadow with the standard `HTTPS_PROXY` setting. For each connection, Shadow looks at the destination host:

- **Known AI host** (for example `api.openai.com`): Shadow terminates TLS with a certificate from its local CA, masks the request, forwards it to the real host over a fresh TLS connection, and restores the response.
- **AI chat app** (ChatGPT, Claude.ai, Gemini, Perplexity, DeepSeek, Grok in a browser or desktop app): the same, but only the requests that send a prompt are masked, and only their prompt text. Sign-in, settings, pages and everything else go through unchanged. Answers and reloaded history are restored.
- **Any other host**: Shadow opens a plain TCP tunnel and copies bytes in both directions. It never sees the content, because it never holds a certificate for that host.

TLS is terminated only on your machine, before the request is encrypted again for the provider.

## 1. Start Shadow

```sh
shadow run                      # foreground
# or, as a background service with the CA trusted:
shadow install --apply
```

## 2. Trust the local CA

`shadow init` creates a CA at `<data dir>/ca/ca.pem`. Its private key is created with mode `0600` and never leaves the machine. The CA is constrained (path length 0) and valid for 10 years. Leaf certificates are minted in memory per host.

`shadow install --apply` adds the CA to the OS trust store. To do it by hand:

<Tabs syncKey="os">
<TabItem label="macOS">
```sh
security add-trusted-cert -r trustRoot \
  -k ~/Library/Keychains/login.keychain-db \
  ~/Library/Application\ Support/shadow/ca/ca.pem
```
</TabItem>
<TabItem label="Debian / Ubuntu">
```sh
sudo cp ~/.local/share/shadow/ca/ca.pem /usr/local/share/ca-certificates/shadow-local-ca.crt
sudo update-ca-certificates
```
</TabItem>
<TabItem label="Fedora / RHEL">
```sh
sudo cp ~/.local/share/shadow/ca/ca.pem /etc/pki/ca-trust/source/anchors/shadow-local-ca.pem
sudo update-ca-trust
```
</TabItem>
<TabItem label="Windows">
```powershell
certutil -user -addstore Root "$env:APPDATA\shadow\ca\ca.pem"
```
</TabItem>
</Tabs>

The running proxy also serves the CA at `http://127.0.0.1:8877/shadow/ca.pem`, which is handy in containers.

### Runtimes with their own trust store

Several runtimes ignore the OS trust store. Point them at Shadow's files:

| Runtime | Variable | Value |
|---|---|---|
| Node.js | `NODE_EXTRA_CA_CERTS` | `ca/ca.pem` (adds to the built-in roots) |
| Python `requests` | `REQUESTS_CA_BUNDLE` | `ca/bundle.pem` |
| Python `httpx`, OpenSSL-based tools | `SSL_CERT_FILE` | `ca/bundle.pem` |
| curl | `CURL_CA_BUNDLE` | `ca/bundle.pem` |

`bundle.pem` contains the system roots plus the Shadow CA, because these variables *replace* the trust store rather than extend it.

## 3. Set the proxy environment

`shadow install` prints the exact lines for your data directory, and `--apply` writes them to `<data dir>/env.sh` (or `env.ps1`):

<Tabs syncKey="os">
<TabItem label="macOS / Linux">
```sh
export HTTPS_PROXY=http://127.0.0.1:8877
export NO_PROXY=localhost,127.0.0.1
export NODE_EXTRA_CA_CERTS="$HOME/Library/Application Support/shadow/ca/ca.pem"
export REQUESTS_CA_BUNDLE="$HOME/Library/Application Support/shadow/ca/bundle.pem"
export SSL_CERT_FILE="$HOME/Library/Application Support/shadow/ca/bundle.pem"
export CURL_CA_BUNDLE="$HOME/Library/Application Support/shadow/ca/bundle.pem"
```
On Linux the paths are under `~/.local/share/shadow`.
</TabItem>
<TabItem label="Windows">
```powershell
$env:HTTPS_PROXY = "http://127.0.0.1:8877"
$env:NO_PROXY = "localhost,127.0.0.1"
$env:NODE_EXTRA_CA_CERTS = "$env:APPDATA\shadow\ca\ca.pem"
$env:REQUESTS_CA_BUNDLE = "$env:APPDATA\shadow\ca\bundle.pem"
$env:SSL_CERT_FILE = "$env:APPDATA\shadow\ca\bundle.pem"
$env:CURL_CA_BUNDLE = "$env:APPDATA\shadow\ca\bundle.pem"
```
</TabItem>
</Tabs>

Add `source "<data dir>/env.sh"` to `~/.zshrc` or `~/.bashrc` to make it permanent.

## System-wide with the system proxy

To cover browsers and desktop apps too, including ChatGPT, Claude.ai and Gemini in a browser, point the machine's system proxy at Shadow:

```sh
shadow install --system-proxy            # dry run: lists every setting it would change
shadow install --system-proxy --apply    # service, CA trust, then the system proxy
```

Or switch it on and off on its own, once Shadow is installed:

```sh
shadow system-proxy status
shadow system-proxy on --apply
shadow system-proxy off --apply
```

On macOS this sets an automatic proxy configuration on every enabled network service (Wi-Fi, Ethernet, ...); on Windows, the setup script in Internet Settings; on GNOME, the automatic proxy. All of them load `http://127.0.0.1:8877/proxy.pac?scope=all`, which:

- sends all traffic to Shadow, except `localhost`, `.local` names and private addresses (`10/8`, `172.16/12`, `192.168/16`, `169.254/16`), which go direct;
- falls back to a direct connection whenever Shadow is not answering (`PROXY 127.0.0.1:8877; DIRECT`), so stopping Shadow never cuts the machine off.

Shadow still decrypts only AI hosts. Every other connection is tunnelled byte for byte and is **not recorded** anywhere: Shadow never becomes a log of your browsing. `shadow uninstall --apply` and `shadow system-proxy off --apply` turn off only settings that point at Shadow and leave any other proxy configuration alone.

<Aside type="caution" title="What the system proxy does not reach">
Apps that ignore the system proxy (many command-line tools, Node.js and Electron apps that bring their own network stack) still need `HTTPS_PROXY` or a base URL, as above. Firefox uses its own certificate store: turn on `security.enterprise_roots.enabled` in `about:config` (on by default in recent versions on macOS and Windows) so it trusts Shadow's CA. AI apps on phones and apps that pin their certificates are not covered. For capture of every connection from every app, see the [macOS Network Extension](https://github.com/Tiny-Bubble-Company/shadow/tree/main/apps/shadow-netext) (a scaffold that needs an Apple Developer ID to build).
</Aside>

### AI chat apps

With the system proxy on and the local CA trusted, these chat apps are masked in a browser or their desktop app:

| App | Host | What is masked |
|---|---|---|
| ChatGPT | `chatgpt.com` | The message you send (`messages[].content.parts`) |
| Claude.ai | `claude.ai` | The prompt and pasted or attached text |
| Gemini | `gemini.google.com` | The prompt (inside the `f.req` form field) |
| Perplexity | `perplexity.ai` | The question |
| DeepSeek | `chat.deepseek.com` | The prompt |
| Grok | `grok.com` | The message |

For each prompt request Shadow reads the goal first, like any other request: if you ask it to write to someone, that person goes through unchanged and everything else is masked. Values are replaced with persona fakes rather than `[PERSON_0001]` tokens, so the fakes can be restored when the app reloads the conversation later. The request's timezone is set to the persona's. Every answer, streamed or not, and the conversation history are restored on your machine, so the chat reads normally while the provider only ever stores the fakes.

Each prompt shows up as an incident in the [activity dashboard](/shadow/concepts/activity-dashboard/), with the app (for example Google Chrome → ChatGPT) and the prompt as written and as sent.

These are the vendors' own web formats, not public APIs, and they change without notice. Support is best effort: a request Shadow does not recognise is forwarded as it is, and WebSocket features (voice, live collaboration) are not processed. Microsoft Copilot, Le Chat, Meta AI and Poe are not supported yet. Turn chat apps off with:

```toml
[proxy]
chat_apps = false
```

### Only AI hosts, with a PAC file

To send only the intercepted AI hosts through Shadow and everything else direct, point an app or the OS at `http://127.0.0.1:8877/proxy.pac` (without `?scope=all`). With this file, chat apps in a browser are masked only if their hosts are on the list, which they are while `chat_apps` is on.

## Which hosts are intercepted

Run `shadow hosts` to list the patterns in effect. They come from Shadow's [catalog of 280+ AI services](/shadow/reference/providers/#the-catalog); services Shadow recognises but cannot mask (Cursor, Windsurf, Amazon Q and other binary protocols) are tunnelled untouched and shown on the dashboard as *seen, not protected*. The built-in list covers model APIs (OpenAI, Anthropic, Google Gemini and Vertex AI, Mistral, DeepSeek, xAI, Cohere, Perplexity, AI21, Reka, Moonshot, Alibaba Qwen, Zhipu, MiniMax, Meta Llama API, Voyage AI), inference clouds (Azure OpenAI and Azure AI services, AWS Bedrock runtime, OpenRouter, Groq, Together, Fireworks, Cerebras, Replicate, Hugging Face, DeepInfra, Hyperbolic, SambaNova, Novita, Lambda, Baseten, NVIDIA NIM, Nebius, SiliconFlow, Cloudflare AI Gateway) and the six chat apps above. The full list is in [Supported providers](/shadow/reference/providers/).

Add hosts, such as a self-hosted LLM gateway, with `extra_hosts`. Exclude hosts with `bypass_hosts`. Both accept `*` globs:

```toml
[proxy]
extra_hosts = ["llm.internal.example.com", "*.inference.example.net"]
bypass_hosts = ["api.cohere.com"]
```

A bypassed host is tunnelled like any non-AI host: never decrypted, never masked.

## Plain HTTP

Absolute-form HTTP requests (`http://host/...` sent to the proxy) are forwarded too. They are masked only if the host is on the intercept list.

## Egress through a relay

Translation hides content, not your IP address. To make AI traffic leave from somewhere else, for example a relay in the persona's region, set an upstream proxy. It applies to intercepted traffic only:

```toml
[proxy]
upstream_proxy = "socks5h://relay.example.net:1080"   # http://, socks5:// or socks5h://
```

## Bypassing Shadow

If Shadow is stopped, tools configured with `HTTPS_PROXY` fail to connect. To bypass it temporarily, unset the variable for one command:

```sh
env -u HTTPS_PROXY your-tool
```

<Aside type="caution" title="Certificate pinning">
Apps that pin their TLS certificates reject any CA they don't expect, including Shadow's. They fail in proxy mode. Use gateway mode for those tools where possible, or add their host to `bypass_hosts`.
</Aside>
