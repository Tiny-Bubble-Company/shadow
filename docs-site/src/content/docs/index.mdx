## Why Shadow

<CardGrid>
	<Card title="Translate, don't block" icon="random">
		DLP gateways block requests, and people route around them. Shadow keeps the prompt
		coherent: a fake email is still an email and a fake IBAN still passes mod-97, so the
		model still gives a useful answer.
	</Card>
	<Card title="Runs on the endpoint" icon="laptop">
		A single Rust binary on macOS, Linux or Windows, or a library inside your service.
		No cloud, no account, no telemetry. The mapping lives in an encrypted vault on the
		machine.
	</Card>
	<Card title="Works with any tool" icon="puzzle">
		Use it as an HTTPS proxy for every app, as a gateway base URL for SDKs, or embed
		`shadow-core` in Rust. Non-AI traffic is tunnelled without decryption.
	</Card>
	<Card title="Stream and tool-call aware" icon="comment-alt">
		Fakes split across SSE events are reassembled and restored. Tool-call arguments are
		restored on your machine before your tools run, so agents keep working.
	</Card>
	<Card title="Intent-aware policy" icon="setting">
		Each request is classified as act, report, code or converse. Reports get typed
		tokens, actions keep working through local tools, and secrets are always redacted.
	</Card>
	<Card title="Files too" icon="document">
		Uploaded text, CSV, JSON, DOCX, XLSX, PPTX and PDF content is masked before it leaves,
		and Office documents stay valid documents.
	</Card>
</CardGrid>
