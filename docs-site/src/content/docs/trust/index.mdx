**Shadow Core runs entirely on your machines and never phones home. Shadow Hub receives only what your organisation's sharing level allows, applied on each laptop before anything is sent: counts only, prompts as the AI received them, or full detail. Non-AI traffic and activity from before a machine joined are never sent.**

## How data flows

```text
 laptop or server                                   your organisation
┌───────────────────────────────────────────┐      ┌─────────────────────────┐
│ apps → Shadow Core → masked request ──────┼────▶ │ AI service (OpenAI, …)  │
│          │  real values stay in the local │      └─────────────────────────┘
│          │  encrypted vault               │
│          └─ events, trimmed to your        │      ┌─────────────────────────┐
│             sharing level (only if         ├────▶ │ Shadow Hub dashboard    │
│             connected to Hub) ─────────────┘      └─────────────────────────┘
└───────────────────────────────────────────┘
```

- **Core is local.** Detection, masking and restoring happen on the machine. The mapping between real values and fakes stays in a local, encrypted vault and is never uploaded.
- **Core never phones home.** No telemetry, update checks or usage statistics. The [source code](https://github.com/Tiny-Bubble-Company/shadow) is open for you to check.
- **Hub is opt-in.** A machine reports to Hub only after someone runs `shadow hub connect` (or the installer from an invite) and confirms. The menu-bar app, local dashboard and `shadow status` show it is managed and what is shared.

## What Hub receives

| Sharing level | Hub receives | Never |
|---|---|---|
| Counts | Per request: time, AI service, app, action (masked, blocked, clean), how many values of each type | Any prompt text |
| Sanitised | Counts, plus the prompt as the AI received it (fakes), the model and the app's process | Real values or the original prompt |
| Full | Sanitised, plus the original prompt, the values caught and conversation ids | |

All levels include the machine's name, operating system and user name, and the person it is enrolled to. No level includes traffic that isn't going to an AI service, or anything from before the machine was connected. Hub enforces the level again on arrival, so an outdated client can't send more than your organisation chose.

## What Hub stores and for how long

- Events and incident details, for your organisation's retention period: **90 days by default**, configurable. Older data is deleted hourly.
- Accounts: admin names and emails, with passwords hashed using Argon2.
- Invite, session and device tokens are stored only as SHA-256 hashes.

## Encryption and access

- All traffic between Core and Hub, and between your browser and Hub, uses HTTPS.
- Each organisation's data is isolated; admins see only their own organisation.
- Admin sign-in uses email and password today; single sign-on is planned.

## Open-source Core

Core is Apache-2.0. Everything that runs on your machines, including the code that decides what is sent to Hub, is in the public repository: [github.com/Tiny-Bubble-Company/shadow](https://github.com/Tiny-Bubble-Company/shadow).
